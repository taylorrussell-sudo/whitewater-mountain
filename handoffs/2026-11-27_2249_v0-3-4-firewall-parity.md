## Changes and decisions

- The dedicated nftables input chain runs at `filter - 10`. It allows loopback and the configured LAN interface, IPv4 source subnet and listening address on the dedicated TCP port. Other input to that port is silently dropped. Other traffic continues through host rules.
- The optional oneshot reads `/etc/whitewater-mountain/firewall.nft`. The static firewall stays bound to the edge through the `whitewater-mountain-edge.service.d/firewall.conf` drop-in. The example network values are generic and configurable.
- The routine upgrade now stages and switches only the reviewed application release. It preserves the installed `service.env` and source opt-ins, the SQLite database and sidecars, installed firewall rules and unit files, and boot enablement. The dedicated Nginx configuration only needs the zone size corrected if it still has the old value. Fresh installation, optional firewall changes, and collector-disabled drills have separate steps.
